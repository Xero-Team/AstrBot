# 配置文件

一份配置文件决定一类会话怎么跑 Agent、用哪套模型、何时唤醒、启用哪些插件。它不是系统设置，也不是针对单个会话的特例。

入口：侧栏 **配置文件**。页面顶部的配置文件菜单可以切换、新建和管理。进程级选项（监听地址、HTTPS、TOTP）在侧栏底部 **设置**，不要和本页混用。

## 默认文件和额外文件

| 配置文件  | 文件                             | 用途                     |
| --------- | -------------------------------- | ------------------------ |
| `default` | `data/cmd_config.json`           | 未匹配到路由时的回退档   |
| 额外文件  | `data/config/abconf_<uuid>.json` | WebUI 创建的命名配置文件 |

绑定关系由配置管理器维护。不要靠重命名 JSON 文件来搬家。设置 `ASTRBOT_ROOT` 后，路径落在 `$ASTRBOT_ROOT/data/` 下。

JSON 必须是严格 JSON：布尔值用 `true` / `false`，不允许注释和尾随逗号。优先用 WebUI 保存；直接改文件后应重启，并先留一份副本。结构说明见 [配置参考](/dev/astrbot-config)。

## 消息怎么选中配置文件

每条消息都有统一消息来源（UMO），格式是 `平台ID:消息类型:会话ID`。例如某个 QQ 群、某次 Telegram 私聊。用 `/session info` 可以查看当前 UMO。

路由表把 UMO 模式绑定到配置文件 ID。匹配不到时使用 `default`。

UMO 三段都可以用通配：

- `::`：全部会话
- `[platform_id]::`：某个平台下的全部类型和会话
- `napcat:GroupMessage:123456`：精确到一个群

匹配优先级从高到低：精确字面值 → 部分通配（如 `group-*`）→ `*` 或空段。同样优先级时保留写入顺序。

绑定入口：

- **机器人** 页编辑平台实例时的会话路由
- ChatUI 为当前 WebChat 会话选择配置文件
- 配置文件页顶部菜单只切换「正在编辑哪一份」，不会自动改路由

保存配置文件后，该文件对应的流水线会重载。改完记得点右下角 **保存**。代码编辑模式要先 **应用此配置**，再保存。

## 和相邻功能的优先级

| 层         | Dashboard         | 管什么                                        | 何时用                   |
| ---------- | ----------------- | --------------------------------------------- | ------------------------ |
| 设置       | 侧栏底部 **设置** | 进程级网络、安全、外观、维护                  | 整台 AstrBot             |
| 配置文件   | **配置文件**      | Agent、模型、`llm_access`、插件集、知识库名单 | 一类会话共用一套行为     |
| 自定义规则 | **自定义规则**    | 单个 UMO 的启停、模型、人格、知识库覆盖       | 少量特例，不要为此再拆档 |

自定义规则高于配置文件。规则里关掉 LLM，配置文件里再开也没有用。详见 [自定义规则](./custom-rules)。

系统设置不会随着配置文件切换。`dashboard.host`、TOTP、反向代理头始终是进程级的。

## 配置文件里常被找错的项

这些都写在配置文件里，不是设置页：

- [群聊何时会理我](./group-wake)：`llm_access`、指令前缀、隔离会话
- [平台处理](./platform-settings)：白名单、限流、内容安全、入站合并
- [语音 STT / TTS](./speech)
- [知识库](./knowledge-base) 的 `kb_names`
- [插件](./plugin) 的 `plugin_set`
- [Persona](./persona)、[Agent 执行器](./agent-runner)

`plugin_set` 默认 `["*"]`，表示使用全部未被插件页禁用的插件。插件页里禁用优先于配置文件勾选。

## 常见误配

1. 改了 `default`，目标群其实绑着另一份配置文件。
2. 为了一个群的人格或模型新建了整份配置文件；这种情况用自定义规则更合适。
3. 在 **设置** 里找唤醒、白名单或 TTS。
4. 编辑 JSON 后没有点「应用此配置」，可视化表单仍是旧值。
5. 把配置文件拷到另一台机器，却没有带上 UMO 路由。
