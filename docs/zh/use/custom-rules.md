# 自定义规则

自定义规则按统一消息来源（UMO）覆盖配置档，用来处理少量特例。不要为了一个群的人格或关 TTS 再拆一份配置档。

UMO 唯一指定某个平台下的一个会话。用 `/session info` 查看。配置档本身见 [配置文件](./config-profiles)。

入口：WebUI **自定义规则**。页面帮助图标指向本页。

## 和配置档怎么选

| 需求                                       | 用什么                                 |
| ------------------------------------------ | -------------------------------------- |
| 整个平台或一类群共用模型、唤醒策略、插件集 | 新建或绑定 [配置档](./config-profiles) |
| 某一个群关掉 LLM、换人格、换知识库         | 自定义规则                             |
| 临时停掉当前会话                           | `/bot disable` 或本页的会话启停        |

规则高于配置档。规则里关掉 LLM 后，配置档再开也没有用。没有规则时，会话默认全部启用（兼容旧数据）。

## 规则类型

每一条规则绑在一个 UMO 上，可以同时包含多类覆盖：

### 服务规则（`session_service_config`）

- 是否处理该会话的消息。关掉约等于把这个 UMO 拉黑。
- 是否对该会话启用 LLM。关掉后不走 AI，指令仍可能执行。
- 是否对该会话启用 TTS。
- 强制人格。优先级高于对话选择和配置档默认人格，见 [Persona](./persona#哪个-persona-会生效)。
- 展示名（`custom_name`）。

聊天里的 `/bot enable`、`/bot disable`、`/llm enable`、`/llm disable` 写的就是这一套服务规则。`/bot status` 可以查看当前会话的整体开关、LLM 和 TTS。这些指令需要 `session.manage`，见 [内置指令](./command)。

### 插件规则（`session_plugin_config`）

为这个 UMO 单独启用或禁用插件。三层同时存在时：

1. 插件页把插件全局禁用：这里勾上也不会加载。
2. 配置档 `plugin_set`：限制该档可用插件。
3. 本规则：再按会话收窄或放行。

详见 [插件](./plugin)。

### 知识库规则（`kb_config`）

- `kb_ids`：覆盖配置档的 `kb_names`。空列表表示这个会话不使用知识库。
- `top_k`、是否重排序：只影响这个会话的检索。

详见 [知识库](./knowledge-base#接到会话)。

### Provider 覆盖

可以为该 UMO 指定聊天模型、STT、TTS。未指定时跟随配置档。语音总开关仍受服务规则和配置档影响，见 [语音 STT / TTS](./speech)。

## 操作步骤

1. 打开 **自定义规则**，点添加规则。
2. 选择已出现过的 UMO，或按平台 / 类型 / 会话填写。
3. 只改需要覆盖的项，不要把无关开关随手关掉。
4. 保存后立即生效，通常不必重启。
5. 删除规则即回到配置档行为。

页面支持按 UMO 搜索、批量删除，以及给规则分组。

## 常见误配

1. 规则关掉了会话或 LLM，群里表现为「机器人不理人」，但 `llm_access` 看起来是对的。先看 `/bot status`。
2. 用规则指定了人格，却还在配置档里改默认人格，当前群不会跟着变。
3. `kb_ids` 填了已删除的知识库 ID，检索会被跳过。
4. 为每个群都建一份配置档，规则表却是空的。
