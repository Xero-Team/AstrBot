# WebUI

AstrBot 管理面板具有管理插件、查看日志、可视化配置、查看统计信息等功能。

![image](https://files.astrbot.app/docs/source/images/webui/image-4.png)

## 菜单与旧入口对照

以下入口对应当前 WebUI 的默认侧边栏。若你调整过侧边栏，可在左下角 `设置 → 外观` 中查看或恢复默认布局。

| 旧入口或称呼                           | 当前入口                                                           |
| -------------------------------------- | ------------------------------------------------------------------ |
| 模型提供商 → 新增提供商 → Agent 执行器 | 配置文件 → 选择配置文件 → AI 配置 → AI 标题旁的 `…` → 更换执行方式 |
| 数据 / 数据统计                        | 更多功能 → 数据与日志 → 统计                                       |
| 对话管理 / 对话数据                    | 更多功能 → 数据与日志 → 对话                                       |
| 日志 / 平台日志                        | 更多功能 → 数据与日志 → 日志                                       |
| 追踪                                   | 更多功能 → 数据与日志 → 追踪                                       |
| 配置 → 普通配置                        | 配置文件 → 选择配置文件                                            |
| 配置文件 → 系统配置                    | 左下角设置 → 常规、外观、网络或安全                                |
| 设置 → 常规 → 缓存 → 导出诊断包        | 设置 → 维护 → 诊断 → 导出诊断包                                    |
| 指令管理                               | 插件 → 管理行为 → 指令                                             |
| 独立 MCP / 技能入口                    | 插件 → MCP / Skills                                                |
| 配置文件 → AI 配置 → 能力 → BTW 双循环 | 更多功能 → BTW 双循环（`/btw`）                                    |
| 工作任务状态与编码代理输出             | 更多功能 → BTW 委派运行（`/btw/runs`）                             |
| 人格设定                               | 提示词设定                                                         |

旧日志、追踪、对话和统计页面地址仍会跳转到对应的新标签页。Agent 执行器现在随配置文件保存，不再通过新增模型提供商创建；操作步骤见 [Agent 执行器](./agent-runner.md)。

BTW 双循环的设置从配置文件页的 AI 面板移到了 `更多功能 → BTW 双循环`（`/btw`）。页面按配置文件加载和保存，内容不变：两个循环的开关与模型、工作循环的只读边界、Computer Use 运行时、委派任务的目录与结果汇报，以及编码代理列表。委派运行页单独展示当前与保留的工作会话、编码代理、最新动作、统一事件时间线、用量与产物；进行中的任务会自动刷新。

`更多功能 → CLI 全局配置`（`/cli-config`）是新增入口：维护 Claude Code 与 Codex 的 provider 列表，并把某个 provider 切换成该 CLI 在本机的默认配置。切换会改写该 CLI 自己的配置文件（会先备份，可“收回”），因此需要 step-up；委派任务读取的是自己那份配置层，不受影响。

启用、收回配置或读取状态时，若弹出二次验证对话框，请按提示验证当前 Dashboard 账户。验证成功后，页面会自动重试对应操作；凭证只用于本次操作，绑定正在运行的默认配置文件。

## 管理面板的访问

当启动 AstrBot 之后，本机可以通过 `http://localhost:6185` 访问管理面板。

> [!IMPORTANT]
> WebUI 默认只监听 `127.0.0.1`。在浏览器中把 `localhost` 换成服务器 IP 不会自动开放远程访问。

需要远程访问时，请显式把 `data/cmd_config.json` 中的 `dashboard.host` 设置为 `0.0.0.0` 或指定网卡地址，重启后再通过服务器地址访问。`0.0.0.0` 会扩大暴露面，请同时配置防火墙，并优先使用 HTTPS 反向代理。完整示例见[源码部署的远程访问说明](/deploy/astrbot/cli#远程访问)。

## 登录

新用户首次登录时，AstrBot 仅在未设置 `ASTRBOT_DASHBOARD_INITIAL_PASSWORD` 时生成随机初始密码。自动生成的密码只显示在连接的运维终端中，不会写入启动日志；外部提供的密码不会显示。用户名通常为 `astrbot`。以服务或容器方式非交互启动时，请在首次运行前通过该变量设置一个临时强密码，登录后立即修改。

当前登录页在未登录前也会公开展示版本信息：

- WebUI 版本
- AstrBot 运行时版本
- 当代码版本与运行时版本不一致时，还会显示 AstrBot 代码版本

如果登录页检测到 WebUI/运行时版本不匹配，或者运行时/代码版本不匹配，会弹出提示对话框，帮助你先处理静态资源版本不一致的问题。

## 单点登录 (OIDC)

AstrBot 可以通过外部 OpenID Connect 提供方认证 Dashboard 用户。该功能默认关闭，本地
密码与 TOTP 登录保持不变。可在 `data/cmd_config.json` 的 `dashboard.oidc` 中配置
（也可在 Dashboard 配置编辑器中配置）：

| 配置项          | 作用                                                                     |
| --------------- | ------------------------------------------------------------------------ |
| `enable`        | 在登录页显示 SSO 按钮。                                                  |
| `issuer`        | 提供方 issuer 地址；AstrBot 读取其 `/.well-known/openid-configuration`。 |
| `client_id`     | 在提供方注册的客户端 ID。                                                |
| `client_secret` | 服务端换取 token 用的密钥，不会下发到浏览器。                            |
| `redirect_uri`  | 固定的回调地址，例如 `https://host/api/v1/auth/oidc/callback`。          |
| `scopes`        | 请求的 scope，默认 `openid profile email`。                              |
| `auto_create`   | 首次验证登录时自动创建 Dashboard 账户（不授予任何角色）。                |
| `button_label`  | SSO 按钮显示的文字。                                                     |

流程使用授权码模式加 PKCE，配合一次性 `state` 与 `nonce` 以及固定回调地址。AstrBot
会通过提供方 JWKS 校验 ID token 签名，并按 `(issuer, subject)` 将外部身份绑定到稳定
的 `account_id`。邮箱仅用于展示，绝不据此授予权限。自动创建的账户不会获得任何角色
绑定，需要运维通过现有授权规则授予权限。当 `auto_create` 关闭时，只有已绑定的身份
可以登录。回调失败或 `state` 被重放时，登录页只显示通用错误。

## 界面与外观

Dashboard 使用响应式侧栏和主内容区：在桌面端可以折叠侧栏并调整其宽度，窄屏会改为覆盖式导航。登录、初始化和已登录页面都可通过外观菜单选择浅色、深色或跟随系统；该偏好只保存在当前浏览器中，不会修改 AstrBot 配置文件。

### 壁纸与界面

**设置 → 外观** 的“壁纸与界面”支持单独维护横屏和竖屏图库。壁纸原图和外观设置保存在服务器，多个 Dashboard 标签页会同步选择；主题模式仍只保存在当前浏览器。

- 支持 JPEG、PNG、WebP 和 GIF，单个文件最大 `32 MiB`。服务器会校验真实格式和像素数，并使用缩略图生成壁纸库预览和主题色。
- 横屏图库用于桌面和横向视口，竖屏图库用于手机和纵向视口；当前方向没有壁纸时回退到另一方向。
- 可以调整填充方式、位置、背景模糊、亮度、饱和度、灰度、遮罩和界面表面透明度。界面表面透明度会同时影响页面、卡片、顶栏和侧栏；浮动菜单保留最低可读底色。
- “界面毛玻璃强度”控制卡片和页面表面的背景模糊；窄屏侧栏有独立的毛玻璃强度。
- “文字可读性增强”提供柔和阴影和强力描边，适合把表面透明度调低后使用。
- “跟随壁纸主题色”会用当前壁纸生成的主色和辅色覆盖主题主色/辅色；关闭后恢复启用前的主题色。
- “打开时随机壁纸”和“定时轮换壁纸”从当前方向的图库中选择，不会连续重复当前壁纸。轮换只在页面可见时运行，并由一个标签页协调。
- 浏览器会把已经鉴权下载的壁纸缓存到本机；删除壁纸会清理对应缓存。清除站点数据或使用无痕窗口会重新下载。
- 删除壁纸会同时移除服务器文件和图库引用，其他标签页会自动回退。壁纸素材包含在 WebUI 数据备份中；外观选择保存在服务器，备份恢复后仍然有效。

GIF 和动态 WebP 在启用“减少动态效果”时会使用静态缩略图，避免持续动画。

## 双因素认证

AstrBot WebUI 支持基于 TOTP（Time-based One-Time Password）的双因素认证。二次因素和受信任设备均属于当前 Dashboard 账户；不同账户需要各自配置，不能通过用户名或全局配置互相继承。

### 开启双因素认证

1. 点击 WebUI 左侧栏底部的 **设置**，进入 **安全** 分区。
2. 打开“启用 WebUI TOTP 双因素认证”开关，WebUI 将显示二维码。
3. 使用任意支持 TOTP 的验证器应用（如 Google Authenticator 等）扫描二维码。
4. 输入验证器应用生成的 6 位验证码完成验证。
5. 系统会生成恢复码，用于丢失验证器设备后的登录。请务必妥善保存。

如需更换 TOTP 密钥，可在 TOTP 管理弹窗中操作，更换时需要先验证当前的 TOTP 验证码。

### 恢复码相关

- 恢复码仅可使用一次。使用恢复码登录后，双因素认证会被自动关闭，需要重新设置。
- 在 TOTP 管理弹窗中可以重新生成恢复码。
- 恢复码丢失时，`data/cmd_config.json` 不是账户二次因素的恢复入口。请联系部署管理员执行账户级恢复；不要通过编辑 `dashboard.totp`、复制 TOTP 密钥或修改数据库来绕过验证。

### 安全性相关

- 启用双因素认证后，更换密钥时需要先验证当前 TOTP 验证码，以防止未经授权的修改。
- 修改管理面板密码会撤销当前账户的所有受信任设备。
- 安装插件、写入凭据、导出数据、重启等高风险操作会要求重新输入当前密码或 TOTP。验证生成的凭证只可用于当前操作一次；取消或验证失败不会执行该操作。

## 设置

系统级设置已经从旧的“配置 → 系统配置”迁移到侧栏底部的 **设置** 页面。页面按常规、外观、网络、安全、维护和 OpenAPI 分区展示；其中“网络”分区包含 HTTP 代理、Python 依赖源和 GitHub 镜像，Docker 下的代理填法见 [Docker 部署](/deploy/astrbot/docker#在-docker-中配置-http-代理)。修改系统设置后会自动保存，并在需要重启时显示提示。

`维护` 中的备份包含会话别名、模型用量统计、OpenAPI 访问密钥和 MCP 服务配置。工作区文件需要单独备份。TOTP 受信任设备记录不纳入备份；替换恢复时会清除现有设备信任，需要重新验证设备。旧备份无法恢复未包含的数据，迁移前请从原实例重新导出备份。如果备份中没有 MCP 配置，则保留目标实例现有的 MCP 配置。

配置文件页面仍用于不同会话路由的 Agent、模型、平台处理和插件配置。不要把“设置”中的系统级网络/安全选项与“配置文件”中的对话行为混为一谈。

## 数据工作区

点击侧栏 **更多功能 → 数据与日志**，可以在 `/dashboard` 通过顶部标签切换 `统计`、`对话`、`日志` 和 `追踪`。首次访问默认显示统计，之后会回到上次使用的标签。运行时 `data/` 文件管理器仍在 `/data`，见[数据文件](#数据文件)。

### 统计

`统计` 页面汇总平台实例、消息、模型调用、Tokens 和运行时间，并展示消息趋势、平台消息排名、模型调用趋势、模型用量排名以及会话模型用量排名。页面可以切换 1 天、3 天或 1 周的统计范围。会话用量会显示 UMO 别名，并可复制原始 UMO，也可以跳转到该 UMO 的对话列表。

该页还包含本地文转图运行状态区，展示进程内 Chromium 连接状态、渲染成功与失败次数、活动页面、耗时、可复用浏览器上下文和累计输出大小。这些数值会在 AstrBot 重启后归零，且不会包含模板、渲染内容、文件路径或用户数据。

### 对话

`对话` 页面用于检索和管理已经保存的对话记录：

- 可以按关键词、机器人 ID、私聊/群聊类型和 UMO 筛选，并按创建时间或更新时间排序。
- 对话列表默认按每页 30 条从服务端分页加载；开启“按会话分组”后，分页单位会切换为 UMO 会话，展开后可查看该会话下的全部对话。只有选中某条对话后，才会加载并在右侧显示完整消息。
- 支持编辑标题、多选导出和多选删除。导出需要二次验证（step-up）。
- 右侧预览顶部的 `{}` 按钮可以在只读 Monaco 编辑器中查看自动换行的原始 `history` JSON。

### 日志

`日志` 页面显示 AstrBot 的实时运行日志，可以按日志级别筛选，也可以从页面中安装缺失的 Pip 库。安装 Pip 库需要二次验证。需要查看 DEBUG 日志时，请先在设置中开启控制台 DEBUG 日志级别。

点击右上角的 `导出诊断包`，确认内容与隐私提示后下载 ZIP。包内包含现有磁盘及轮转日志、自定义路径日志、最近最多 500 条缓存、可用的 Trace 历史、配置及路由、插件版本与状态、运行环境和导出清单。未开启文件日志或 Trace 时，仍可导出已有内容；没有 Trace 历史时会在清单中注明，不会自动开启 Trace。Trace 历史最多导出最近 50 条、合计 16 MiB；磁盘日志合计最多读取 256 MiB、单文件超过 64 MiB 时会跳过，脱敏模式下过长的日志行也会跳过，截断和缺失会记入清单，不包含原始数据库或插件源码。导出弹窗默认勾选 `脱敏导出（推荐）`，自动遮盖已识别的凭据，公网 IPv4/IPv6 地址替换为包内一致的 `[PUBLIC_IP_1]` 等编号，保留协议、端口、路径及内网、回环等非公网地址；同一 IP 的不同写法使用同一编号，不在包内附带原始 IP 对照表，但仍可能包含聊天内容和个人信息，分享前请检查。排障需要原始内容时可取消勾选；此时会保留密码、密钥、Token、公网 IP 等敏感信息，文件名带有 `raw` 标记，请仅私下提供给可信的诊断人员，勿公开上传。每次打开弹窗都会恢复默认勾选。仅控制台管理员可下载，开发者 API Key 不可使用。`设置` → `维护` 中的 `诊断` 使用同一导出功能。

导出弹窗提供 `近 1 小时`、`近 12 小时`、`近 1 天`、`近 3 天` 和 `自定义`，默认选择 `近 1 天`。快捷范围按点击下载时的当前时间计算；选择 `自定义` 后可按浏览器本地时间填写开始和结束时间。仅导出范围内的磁盘日志、缓存日志和 Trace；磁盘日志中的无时间戳续行跟随上一条记录，无法关联到带时间戳记录的内容会排除。磁盘日志未注明时区时按服务端本地时间解析。Trace 按开始时间筛选并保留完整链路，范围内仍最多导出最近 50 条、合计 16 MiB。配置、插件状态和运行环境为导出时的当前快照，所选范围记录在 `manifest.json` 中。

诊断包中的内存日志位于 `logs/astrbot.in-memory.log`，内存 Trace 位于 `traces/history.in-memory.jsonl`，持久化 Trace 历史位于 `traces/history.jsonl`。`environment.json` 的 `webui_version` 记录当前提供服务的 WebUI 资源版本，无法读取时为 `null`。

点击搜索框左侧的“过滤器”，可按日志级别、来源（系统/插件）、具体插件、机器人平台筛选；这些条件可与“搜索日志”叠加使用。插件优先显示 display name，菜单副标题显示插件 ID；“系统”对应原先的 Core 来源。

工具栏还提供字号调整（默认 12px，可按 2px 步长在 8–16px 之间调整），以及“排除用户对话”和“自动滚动”开关。关闭“自动滚动”后，上翻查看旧日志时不会被拉到最新日志。日志仍使用内存缓存，不新增文件读取或数据库持久化。

### 追踪

包含 Agent 调用时，详情统计区增加无边框的 Tokens 卡片，展示本轮输入（含缓存输入）与输出的累计总量，以两位小数的 k/M 格式显示，悬浮提示保留精确数量；悬停或键盘聚焦可查看输入、输出及缓存命中明细。同一 Agent 的累计快照只取最新一份，多个 Agent 分别累计。没有已上报用量时显示“—”，不按 0 处理。

“Agent 执行”标题后显示已记录的模型 ID、人格 ID，以及非零的实际工具调用次数。模型标签悬停可查看提供商 ID，执行链折叠后标签仍可见；嵌套或并行 Agent 分别统计，缺失的信息不显示。

详情标题下的 UMO 和发送人分别以“图标 + 值”独立成行，不再使用点分隔；UMO 别名仍可悬停查看完整标识。

追踪区域和悬停提示使用系统默认字体，不使用 Outfit。运行中状态为蓝色，已完成和错误仍分别为绿色和红色。

列表和详情时间戳按浏览器本地时区显示月、日，格式为 `MM-DD HH:mm:ss.SSS`；时间线悬停提示使用同一格式。

UMO 前新增“类型”列：蓝色 Agent 表示 Agent 调用，绿色“指令”表示指令处理器调用；群聊/私聊使用中性标签独立显示。同一追踪可同时显示这些标签；普通监听器和事件钩子不算作指令。消息类型优先读取追踪摘要，旧记录从 UMO 推导，无法确定时不显示群聊/私聊标签。旧记录的指令标记按当前页数据推导，无需逐条打开详情。

新 Span 使用 `astrbot.kind` 表示调用类型，起止时间和状态表示执行结果；不再存储 `astrbot.action`、`astrbot.end_action` 或 `astrbot.duration_ms`。耗时由纳秒起止时间计算，`astrbot.handler_type` 保留。旧追踪仍可读取，历史数据库记录不会自动重写。

长消息标题默认显示 2 行，收到消息和发送响应的正文默认显示 4 行；超出时可点击“展开全文 / 收起”。这仅折叠界面展示，不截断已记录内容。

“完成”表示整条事件的处理已结束，而不是模型请求或响应发送单独结束。普通消息和 Cron 定时任务共用事件执行生命周期；Cron 不经过消息 Pipeline，在 Agent 执行和历史保存结束后完成追踪，异常或取消也会结束并标记错误。

详情时间线采用紧凑分组布局：“触发插件处理器（类型）”改为“调用插件”配合类别标签，“启动 Agent”改为“Agent 执行”。节点右侧统一显示展开箭头，不再每条单独占一行显示“查看详情”；点击普通节点标题查看原始数据，点击调用插件组展开各次调用。平台 ID 放入次行标签，元信息标签使用中性色；时间改为相对追踪开始的偏移，悬停可查看精确时间。

Agent 默认折叠内部执行链，点击“Agent 执行”可展开请求准备、工具和插件钩子；“原始数据”可进一步查看 Agent 自身的字段。折叠按实际 Span 父子关系识别，不把时间上交错的其他分支误归入 Agent；展开仍保持记录顺序，最终响应保留在主线上。内部错误在折叠标题中也会提示，展开/收起不改变调用、响应或 Span 统计。

![紧凑分组时间线与默认折叠的 Agent（示例数据）](images/trace-timeline-zh.jpg)

“设置 → 常规”中的“日志与缓存清理”现为“日志、缓存与追踪清理”，总占用包含追踪数据库及其附属文件。菜单新增“清理追踪数据”；“全部清理”也包含历史追踪。清理前会确认，已完成或中断的追踪将永久移除，运行中的追踪保留；数据库文件本身不会直接删除。“清理日志”和“清理缓存”不会清除追踪。

在“设置 → 常规 → 日志”中可切换“启用追踪记录”，与追踪页工具栏的启动/暂停按钮共用同一个全局配置；关闭后不再采集新追踪，历史仍可查看。其下可配置“追踪数据库路径”“追踪数据库容量预算 (MB)”和“追踪保留天数”，默认分别为 `logs/traces.db`、80 MB 和 7 天；更改数据库路径后重启后端。系统提示词等顶层文本字段没有单独的 4 KB 截断限制，但整条追踪的内容和节点预算仍然生效。

追踪标签页不使用外层灰色卡片，工具栏和列表直接铺在页面上，仅保留必要的分隔线。原来的顶部说明和独立记录开关已移除；工具栏按钮显示“暂停”（启用且已连接）、“连接中”（启用但未连接）或“启动”（停用）。过滤器、记录按钮、刷新均采用图标加文字的浅灰按钮，与搜索框共用背景色，统一为 36px 高；搜索框填满剩余宽度，将操作按钮靠右排列。记录数量并入占位文字：“在 X 条记录中搜索消息、会话、插件”，不单独显示。点击记录按钮可暂停或恢复，更新期间显示加载状态并禁用重复点击；失败时保持原状态并提示错误。暂停不会清除已有列表或关闭详情，明暗主题保持相同布局。

`追踪` 页面实时显示消息执行链：收到消息、触发插件处理器、Agent 相关请求、发送响应和完成。默认只展示全宽 Vuetify datatable 追踪列表，列顺序为状态标签（运行中/已完成/错误）、平台 logo、时间戳、时长、消息、类型、UMO、发送人和 Spans；表头和单元格字体为 13px，表头高度为 40px，内容行高和间距采用 Vuetify 默认样式，仅定制状态、平台图标及消息等单元格内容。状态标签使用 flat 样式；平台列宽度为 80px，表头不会换行。时长在执行期间持续更新。点击某行后才打开右侧时间线详情，点击关闭按钮或按 Escape 返回列表；加载历史记录、新记录到达及筛选变化都不会自动打开其他记录的详情。窄屏列表可横向滚动。Spans 统计实际 Span 数（包括消息根 Span），不包含挂载在 Span 上的事件，折叠不改变计数；搜索占位文字显示满足当前条件的消息 trace 总数。历史记录在服务端搜索、筛选和分页；原来的“加载更多”改为 Vuetify datatable 分页器，默认每页 50 条，可选 25、50、100 条，并支持前后翻页和首尾页。浏览器只保留当前页摘要，只有当前打开的 trace 加载完整详情，关闭后释放详情。搜索或筛选会返回第一页；新记录只实时刷新第一页，不打乱正在查看的历史页。点击搜索框左侧的“过滤器”，勾选“有错误”“有模型调用”“有插件调用”；多选需同时满足所有条件，并可叠加搜索。不勾选则显示全部，“重置”清除勾选，关闭侧栏仍保留条件。原先的“全部 / 错误 / Agent / 插件”单选标签已改为多选侧栏。工具栏记录按钮可启用或禁用追踪记录。

UMO 有别名时显示别名，带点划线的文字可悬停查看完整 UMO。插件优先显示 display name，悬停可查看插件 ID，同时展示 Handler 名称及耗时。事件监听器不再重复显示底层类型 `AdapterMessageEvent`，其他事件钩子的类型仍保留。插件处理器节点优先使用插件 logo，没有 logo 或加载失败时使用插件卡片的默认蓝色星形图标；标题旁的中性标签展示与插件详情页一致的分类：指令/指令组、事件监听器、事件钩子或 LLM 工具。

> [!NOTE]
> 追踪持久化到独立 SQLite：默认 `data/logs/traces.db`，保留 7 天，容量目标 80 MB，按完整 trace 淘汰最旧数据。WAL 和检查点可能暂时增加占用，容量不是瞬时硬上限。暂停后仍可查看历史，已开始的 trace 会完成记录；重启时未完成的 trace 标为错误/中断。写入队列满或存储失败时页面显示警告，不阻塞消息处理。旧 JSONL 不再写入，也不自动导入；普通日志仍沿用原有文件设置。

处理器名称也带有点划线，悬停时才请求插件详情并展示该 Handler 的 description（包括指令组内的子指令），与插件详情页使用同一份说明。详情在当前页面内缓存；加载失败时再次悬停可重试。

流式响应在发送结束后仅展示一条最终汇总的“发送响应”，不展示中间分片或协议收尾帧。流式生成期间，工具或插件单独发送的消息仍会作为独立响应展示。

时间线使用标签展示元信息：Agent 节点沿用配置文件页的执行器名称，不加“执行方式”前缀，`local` 显示为“AstrBot 内置 AI”；插件处理器显示插件名称，折叠组中的多个名称以逗号分隔。“系统发送 / 插件发送”标签已移除：`event.send()` 和 `Context.send_message()` 等公共发送方法记录成功发送的消息 outline，不再记录来源。`Context.send_message()` 关联当前事件执行，没有活跃事件时不额外创建追踪；嵌套转发只记一次。流式响应仍只保留最终汇总，工具单独发送的消息独立保留。

时间线上连续的同类型节点默认折叠，例如“调用插件”配合“事件监听器”标签，显示记录数量及叠放图标；点击可展开或收起每条记录。不同处理器分类或被其他类型节点隔开的记录不会合并，执行顺序保持不变。组内有错误时，折叠标题仍会提示错误数量，统计卡片仍按实际调用次数计算。

左侧消息列表及“收到消息”节点显示平台 logo；“收到消息”节点的次行标签显示 `platform_id`。没有匹配图标或图片加载失败时使用通用图标，处理状态仍通过文字显示。原先的“选择人格”独立节点已移除，实际选中的 `persona_id` 在“准备 Agent 请求”的详情中显示。搜索框提示为“在 X 条记录中搜索消息、会话、插件”，统计卡片显示耗时、插件处理器次数和发送响应次数，不展示步骤数。

## ChatUI

AstrBot 内置 ChatUI，可在浏览器中直接与已配置的模型对话。

ChatUI 支持以下常用能力：

- 左侧会话列表初始加载最近 30 个会话。滚动到接近底部时会自动加载更早的会话，加载过程中显示进度条。请求失败后会暂停自动加载，选择 **重试** 可继续。若会话数量不足以填满侧栏，会自动继续加载下一页。通过 URL 打开较早的会话时，其标题与选中项会在会话页加载完成前保持可见。
- 创建、重命名、删除对话，并在左侧会话列表中切换历史对话。
- 在聊天页选择配置文件、模型提供商与模型；如果启用了 Provider 会话隔离，也可以为当前会话单独选择模型。
- 发送文本、图片、文件与语音输入；上传附件时会展示预览，并根据文件签名辅助识别文件类型。
- 查看模型思考过程、工具调用状态、知识库或网页搜索引用来源，以及每条回复的 Token 和耗时统计。
- reasoning 默认显示。可从输入框菜单为当前请求、重新生成或线程单独切换 reasoning 显示。
- 对已有回复执行复制、重新生成，或使用其他模型重新生成。
- 编辑用户消息后从该消息继续生成，也可以针对某段内容开启分支追问。
- 切换流式/普通响应模式，以及 SSE/WebSocket 通信模式。触摸或粗指针设备上，传输模式和语言的二级菜单改为点击打开，避免悬停无法展开。

如需恢复使用所选配置文件中的默认模型，打开模型选择器，点击 **默认模型**（**跟随配置文件默认模型**）。这会清除当前对话的模型覆盖，其他对话保存的模型选择不受影响。退出登录会清除此浏览器中保存的所有 ChatUI 模型选择。

- 可在 ChatUI 中浏览当前项目工作区。文本预览使用 Shiki 语法高亮并跟随当前浅色或深色主题；二进制文件只显示元数据。

### 分享对话

在左侧会话列表中，悬停某个会话并点击分享按钮，即可为该会话创建只读分享链接。链接无需登录即可打开，任何拿到链接的人都能阅读该会话的文本记录，请谨慎分享。

- 有效期可选 1、7、30、90 天或永不过期。
- 原始链接只在创建时显示一次，之后无法找回；请立即复制保存。
- 公开页面只呈现该会话的纯文本记录（不包含附件），不能写入，也访问不到你的其他数据。
- 可在同一对话框查看该会话已有的分享链接，并随时撤销；被撤销或过期的链接会显示为不可用。
- 会话消息过多时只展示最近的记录，并在页面顶部提示。

> [!WARNING]
> 分享链接本身就是访问凭证。任何持有链接的人都能读取该会话，请不要分享包含敏感信息的对话。

### 并行模型

多模型并行默认关闭。在 `data/cmd_config.json` 中开启 `dashboard.chatui_multi_model.enable`，并通过 `dashboard.chatui_multi_model.max_models` 设置一次提示词最多可选的模型数（2–8，默认 3）。在 ChatUI 中点击模型选择器旁的 **对比模型**，为下一条提示词选择多个模型。每条回答会作为分支随助手消息保存，可在回复头部的分支按钮间切换。所选模型中的第一个会写入当前会话的模型选择。

### ChatUI 中的高风险工具

消息框旁的盾牌钥匙按钮可为一次 ChatUI 运行启用高风险工具。只有当前登录的
Dashboard 账户在所选配置文件上拥有 `instance_operator` 或更高角色绑定时，才可使用
此功能。确认弹窗会要求输入当前密码或 TOTP 验证码。

确认后仅会授予以下实例级工具 action：

- 本机 Shell 和 Python 执行；
- 本机文件写入；
- 浏览器和 Computer Use 控制；
- 具有写入能力的 MCP 工具。

凭证只保存在浏览器内存中，并绑定当前 WebChat 会话和配置文件。下一次运行启动时会
消耗并丢弃它；切换会话或配置文件、等待凭证过期，或再次点击按钮停用后，都需要重新
启用。再次执行高风险运行前，也需要重新启用。

此功能不会授予修改账户、提供商、插件、系统设置、导出或重启等全局 Dashboard
操作权限。账户现有的 Prompt、工具、本地隔离和路径限制仍然生效。匿名 WebChat、API Key、
IM 消息、插件和后台续跑不能复用该授权。IM 发送者要使用同一组实例工具，需把
`/session info` 里的授权主体绑成该配置的 `instance_operator`，见 [授权管理](./authorization)。

> [!NOTE]
> 为保证消息接收顺序，同一浏览器会话建议只保留一个 ChatUI 页面。如果你在多个标签页中同时打开聊天页面，系统可能会提示需要重新建立连接。

## 账户与权限

WebUI 支持多个 Dashboard 账户。首次启动会创建 bootstrap `root` 账户（用户名通常为 `astrbot`）。控制面身份来自账户表和角色绑定，不能凭用户名推断 `root`。

侧栏 **更多功能 → 授权管理** 打开 `/authorization`。Dashboard 账户、IM 会话 owner 和 `/admin grant` 不是同一套身份；群聊授权、二次验证（step-up）和角色表见 [授权管理](./authorization)。

跨会话监听、连接和 `/send` 目前没有 Dashboard 管理面。绑定 `instance_operator` 后，只能在 IM 或 WebChat 里用 [内置指令](./command#跨会话监听与发送) 创建、查看和停止监听或连接。指令管理页可以启用或禁用这些指令，但不会列出活跃监听或连接。

开发模型见[项目架构](/dev/architecture#统一授权系统)。

## 提示词

在提示词页面可以创建文件夹、移动/排序提示词，并导入或导出单个提示词。导出 JSON 只包含提示词 ID、系统提示词和预设对话，不包含工具与 Skills 配置；导入后需要重新检查并手动配置工具、Skills 和 Provider。

如果导入文件中的提示词 ID 已存在，WebUI 会为新提示词生成带 `_imported` 后缀的 ID，避免覆盖现有内容。导入前仍应检查 JSON 来源，不要把不可信系统提示词直接用于高权限 Agent。

## 指令管理

通过左侧菜单 `指令管理`，可以集中管理所有已注册的指令，默认不显示系统插件。

支持按插件、类型（指令 / 指令组 / 子指令）、权限与状态过滤，配合搜索框快速定位。指令组行可展开查看子指令，徽章显示子指令数量，子指令行会缩进区分层级。

可以对每个指令启用/禁用、重命名并修改别名。所属插件未启用时，指令行会显示为「未启用」，启用/禁用和重命名会禁用，但仍可查看详情；这些指令也不参与冲突检测。保存后，插件生命周期持有的不可变指令 catalog 会立即重建；已启用原生命令注册的 Telegram 和 Discord 适配器也会立即刷新菜单或 slash commands，不需要等待下一次消息处理。

指令以稳定 `command_id` 标识，格式为 `插件名:原指令路径`（空格换成点），例如 `builtin_commands:plugin.list`。权限覆盖只读写该键；Python 方法名和历史短名键会被忽略。未在 Dashboard 手动重命名的内置指令始终使用当前声明名。无法按 `handler_full_name` 或 `command_id` 认领的旧 `command_configs` 行会在同步时删除。

## 数据文件

侧栏 **更多功能 → 数据文件** 打开 `/data`，用于浏览和编辑当前运行时 `data/` 目录。它不是远程 IDE：没有终端、代码执行、Git 或任意宿主机路径。

桌面端左侧是目录树，中间是文件标签和 Monaco 编辑器。URL 只保存相对路径，例如 `/data?path=skills/demo/SKILL.md`，不保存文件内容或凭据。非法路径会回退到 `data/` 根目录。隐藏文件会显示。未保存修改离开页面时会弹出确认。

`operator` 和 `root` 可以浏览普通文本并保存。文本上限 1 MiB，超过后改为只读下载。可创建、重命名、移动、删除文件和目录，上传单文件不超过 32 MiB，并按文件名搜索（不搜索内容）。图片和音频可预览；数据库、压缩包和未知二进制只提供元数据和下载。

受保护路径单独授权：

- `plugins/` 默认只读，删除或写入需要 root 的 `filesystem.manage` step-up。
- `dist/`、`site-packages/`、`astrbot.lock` 和正在使用的数据库及其 WAL/SHM 始终不可写。
- `cmd_config.json` 和 `config/` 的原文读取仅限 root；普通配置仍应走结构化配置页。
- demo mode 只读。
- API Key 不能访问该页面。

并发保存使用 etag：磁盘内容变化时返回冲突，可选择保留本地或重新加载。开发模型见[项目架构](/dev/architecture#数据文件管理器)。

## 更新管理面板

本 fork 不提供 Dashboard 一键 Core 更新。源码部署应在更新 checkout 后重新构建 `dashboard/dist`，再运行 `uv run python scripts/sync_dashboard_dist.py`，具体命令见[源码部署](/deploy/astrbot/cli#更新-checkout)。

消息指令和 `astrbot` CLI 都不会下载、安装或更新 Dashboard。上游 Dashboard 静态资源与当前 fork 的后端 API 和前端功能不兼容，不应复制到 `data/dist`。启动时只使用显式 `--webui-dir`、当前源码树构建产物、随包资源或版本匹配的 `data/dist`；没有兼容构建时，后端继续运行，但 WebUI 不可用。

## 自定义 WebUI 端口

修改 data/cmd_config.json 文件内 `dashboard` 配置中的 `port`。

## 忘记密码

停止 AstrBot 后使用 CLI 重置：

```bash
uv run astrbot password
# 或
uv run astrbot run --reset-password
```

> [!TIP]
> 详细说明请参阅 [FAQ - 忘记 WebUI 密码](/faq#忘记-webui-密码)。不要手工删除密码哈希或 JWT 密钥字段。
