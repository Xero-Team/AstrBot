## [4.28.2] - [WIP]

### Added

- Add top-level `admission.unlisted_sessions` (`allow` / `deny`) after the
  wake check. Default `allow` admits sessions with no overlay. `deny` admits
  only groups or DMs that already have an overlay on the canonical session
  key. (#215)
- Add top-level `admission.unlisted_senders` (`allow` / `deny`) and
  `/user block`, `/user unblock`, `/user llm on|off` (`session.manage`).
  Default `allow` admits senders with no overlay. `deny` admits only IM
  subjects that already have a `blocked` or `llm_enabled` overlay. (#216)
- Custom rules can target sender overlays (`blocked` / `llm_enabled`) on the
  same `scope=sender` preference row as `/user`. (#217)
- Persist session-bridge dedup keys and the quote-id map in the new
  `session_bridge_deliveries` table, so a restart no longer re-forwards an
  accepted message or loses cross-platform reply ids. `terminate()` keeps the
  persisted rows. (#245)
- Add a session-bridge delivery-health snapshot and `/session health`
  (`session.read`) with accepted / partial / failed / unknown / skipped
  counters, skip reasons, pending forwards, and bounded per-rule last errors.
  (#252)
- Expose session-bridge pair, link, filter, and quota operations on the plugin
  `SessionBridgeCapability`; `/session pair|unpair|links|unlink|filter` use the
  same public surface, and `SessionBridgeQuota` is exported from
  `astrbot.api.platform`. (#251)
- Report live session-bridge watch / connect / pair quota usage in the command
  replies instead of fixed catalog literals. (#262)
- Add the JEV System One classifier provider and experimental capability
  routing, with Dashboard guidance and validation for its HTTPS endpoint, key,
  model, and timeout, plus a bounded fallback model. (#272, #276, #277)
- Add `platform_settings.onebot_forward.{expand_on_ingress,max_fetch}` and
  `t2i_forward_card`: OneBot v11 merged forwards are expanded at ingress and
  rendered as a t2i image card on targets without native `forward`, falling
  back to the labeled transcript. (#281, #285)
- Bundle provider icons under `dashboard/src/assets/images/provider_logos/`
  instead of resolving them from `cdn.jsdelivr.net` and vendor CDNs. (#282)

### Changed

- IM `/llm disable` and `/llm enable` write the canonical session key, so a
  unique-session group shares one LLM switch. Existing unique-session UMO
  `llm_enabled=false` rows are not dual-read. Dashboard custom-rule LLM,
  session-enabled, and block fields dual-write that canonical key. (#215)
- Treat an unwritten IM session / LLM / TTS overlay as off; Dashboard WebChat
  stays on. Operators opt in with `/bot enable`, then `/llm enable` or
  `/tts enable`. This is a breaking change. (#237)
- Make the sender custom-rule LLM control tri-state (follow session / enabled /
  disabled) and stop materializing an absent `llm_enabled`, so an untouched
  sender rule keeps following the session. (#239)
- Serialize session-bridge delivery per destination instead of with one
  process-wide lock, and drain each origin to listener edge FIFO so a burst
  keeps its arrival order. (#244, #247)
- Retry session-bridge forwards a bounded number of times and release the dedup
  claim when no attempt is accepted, instead of dropping on the first transient
  failure. (#243)
- Count and throttle-log dropped envelope forwarding, dispatch all observers
  together, and expose `dispatch_stats` on `GET /api/v1/bots/stats`. (#246)
- Name the specific quota in `/session watch|connect|pair` rejections. (#248)
- Surface failed project create, rename, and delete in the Dashboard, keep the
  dialog open, and refresh the list only on success. (#240)
- Report a failed WebChat config-profile bind and reconcile the selector and
  stored profile with the backend-resolved value. (#241)
- Restore native replies for bridged quotes when the accepted-message id
  mapping exists, and otherwise degrade to a readable quote summary instead of
  a raw numeric id. (#280)
- Rename the `persona` subsystem to `prompt`: `persona_id` becomes `prompt_id`,
  `/persona` becomes `/prompt`, `/api/v1/personas` becomes `/api/v1/prompts`,
  the `personas` / `persona_folders` tables become `prompts` / `prompt_folders`,
  and `Personality` becomes `PromptSpec`. No shims or aliases are provided.
  This is a breaking change. (#273)

### Removed

- Remove `id_whitelist`, `enable_id_white_list`, `id_whitelist_log`, and
  `wl_ignore_admin_*`. Dashboard writes that include those fields fail.
  Empty or disabled lists become `allow`. A non-empty enabled list becomes
  `deny` plus a per-profile listed-session set. Unique-session UMOs unwrap
  to the group id. WebChat, OneBot `notice` / `request`, and senders with
  `provider.manage` skip unlisted-session deny. This is a breaking change.
  (#215)
- Remove the always-true `session_bridge_rules.header` column and its dead
  update branch; the localized source header is always prepended. The main
  database still requires the documented empty-database cutover. (#250)
- Remove the unused `persona_runtime` subsystem and its four tables. The
  long-term memory (Alkaid) feature is unchanged. (#273)

### Fork Deviations

- Upstream release wording and upstream-only artifact links are not copied
  verbatim; this changelog describes the features present in the fork.
- Absorbed upstream windows are recorded per commit in `upstream-sync.yaml`
  and `upstream-decisions.jsonl` rather than repeated here.

## 中文

### 新增

- 在唤醒检查之后加入顶层 `admission.unlisted_sessions`（`allow` / `deny`）。
  默认 `allow` 放行没有覆盖的会话；`deny` 只放行规范会话键上已有覆盖的群或
  私聊。(#215)
- 加入顶层 `admission.unlisted_senders`（`allow` / `deny`）以及 `/user block`、
  `/user unblock`、`/user llm on|off`（需要 `session.manage`）。默认 `allow`
  放行没有覆盖的发送者；`deny` 只放行已有 `blocked` 或 `llm_enabled` 覆盖的
  IM 主体。(#216)
- 自定义规则可以编辑发送者覆盖（`blocked` / `llm_enabled`），与 `/user`
  写入同一行 `scope=sender` preference。(#217)
- 会话桥接的去重键和引用消息 ID 映射持久化到新的 `session_bridge_deliveries`
  表：重启后不再重复转发已接受的消息，也不再丢失跨平台回复 ID。`terminate()`
  不会清除已持久化的行。(#245)
- 加入会话桥接投递健康快照与 `/session health`（需要 `session.read`），包含
  接受 / 部分 / 失败 / 未知 / 跳过计数、跳过原因、排队中的转发，以及有上限的
  按规则最近错误。(#252)
- 在插件 `SessionBridgeCapability` 上开放会话桥接的配对、链路、过滤和配额操作；
  `/session pair|unpair|links|unlink|filter` 使用同一套公开接口，
  `SessionBridgeQuota` 从 `astrbot.api.platform` 导出。(#251)
- 会话桥接的 watch / connect / pair 配额回复显示实时用量，而不是写死的文案。
  (#262)
- 加入 JEV System One 分类器 provider 与实验性能力路由，Dashboard 对其 HTTPS
  端点、密钥、模型和超时提供引导与校验，并带一个有界的兜底模型。
  (#272、#276、#277)
- 加入 `platform_settings.onebot_forward.{expand_on_ingress,max_fetch}` 与
  `t2i_forward_card`：OneBot v11 合并转发在入口展开，目标平台不支持原生
  `forward` 时渲染为 t2i 图片卡片，失败则回退为带标签的记录。(#281、#285)
- 把 provider 图标内置到 `dashboard/src/assets/images/provider_logos/`，不再从
  `cdn.jsdelivr.net` 和各厂商 CDN 加载。(#282)

### 变更

- IM 的 `/llm disable` 和 `/llm enable` 写入规范会话键，因此隔离会话下会关掉
  整个群的 LLM。旧的隔离会话 UMO `llm_enabled=false` 行不再双读。Dashboard
  自定义规则会把 LLM、会话启用和完全禁用双写到该规范键。(#215)
- 未写入的 IM 会话 / LLM / TTS 覆盖一律视为关闭，Dashboard WebChat 保持开启。
  运营者需先用 `/bot enable`，再 `/llm enable` 或 `/tts enable`。这是破坏性
  变更。(#237)
- 发送者自定义规则的 LLM 控制改为三态（跟随会话 / 启用 / 禁用），不再在缺少
  `llm_enabled` 时凭空写入布尔值，未改动的发送者规则会继续跟随会话。(#239)
- 会话桥接投递按目标串行，而不再使用单个进程级锁；每个「来源到监听方」边按
  FIFO 排空，突发消息保持到达顺序。(#244、#247)
- 会话桥接转发会进行有限次重试，并在没有任何尝试被接受时释放去重占用，而不是
  在首次瞬时失败时直接丢弃。(#243)
- 被丢弃的 envelope 转发会计数并按 30 秒节流记录日志，同一事件的所有观察者
  一起派发，并在 `GET /api/v1/bots/stats` 暴露 `dispatch_stats`。(#246)
- `/session watch|connect|pair` 被配额拒绝时会说明具体是哪个限制。(#248)
- Dashboard 会显示项目创建、重命名、删除失败，保持对话框打开，只在成功时刷新
  列表。(#240)
- WebChat 配置档绑定失败会被上报，并把选择器和已存配置档对齐到后端实际解析的
  值。(#241)
- 桥接引用消息在存在已接受消息 ID 映射时恢复为原生回复，否则降级为可读的引用
  摘要，而不是裸数字 ID。(#280)
- 把 `persona` 子系统整体改名为 `prompt`：`persona_id` 变为 `prompt_id`，
  `/persona` 变为 `/prompt`，`/api/v1/personas` 变为 `/api/v1/prompts`，
  `personas` / `persona_folders` 表变为 `prompts` / `prompt_folders`，
  `Personality` 变为 `PromptSpec`。不提供 shim 或别名。这是破坏性变更。(#273)

### 移除

- 删除 `id_whitelist`、`enable_id_white_list`、`id_whitelist_log` 和
  `wl_ignore_admin_*`。Dashboard 写入这些字段会失败。空列表或关闭的白名单变成
  `allow`；非空且开启的列表变成 `deny`，并按配置档记入列入集。隔离会话 UMO
  会解开成群 ID。WebChat、OneBot 的 `notice` / `request`，以及拥有
  `provider.manage` 的发送者会跳过未列入会话拒绝。这是破坏性变更。(#215)
- 删除恒为真的 `session_bridge_rules.header` 字段及其死分支；本地化来源头始终
  会前置。主库仍需按文档执行清库切换。(#250)
- 删除未使用的 `persona_runtime` 子系统及其四张表。长期记忆（Alkaid）功能不受
  影响。(#273)
