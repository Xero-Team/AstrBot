# 知识库

知识库把文档切块、做成向量，在对话时检索相关片段。本 fork 只支持现行工作流；旧流程不再作为正式路径。

入口：侧栏 **知识库**。在 **配置文件 → AI 配置 → 知识库** 中选择要绑定的知识库。

![知识库预览](https://files.astrbot.app/docs/zh/use/image-3.png)

## 准备模型

1. 打开 **提供商**，新增 **Embedding**。当前内置类型包括 OpenAI 兼容、Gemini、NVIDIA NIM 和 Ollama。
2. 可选：再新增 **重排序（Rerank）**。内置类型包括 vLLM 兼容、Xinference、百炼和 NVIDIA。
3. 保存后来到 **知识库**，创建知识库并选好嵌入模型（重排序可选）。

选定嵌入模型后，不要再改该提供商的**模型名**或**向量维度**。已有 FAISS 索引不会自动迁移，召回会失败甚至报错。NVIDIA 内置默认模型若有变更，已保存的 Provider 和已建索引同样不会自动迁移。

## 上传与分块

创建后即可上传。可以一次选多个文件，也可以拖入整个文件夹（例如一批 Markdown）。嵌套目录会递归收集受支持的文档。每批不再限制 10 个文件，单个文件不超过 128 MB。

![上传文件](https://files.astrbot.app/docs/zh/use/image-4.png)

上传时可覆盖分块参数；知识库设置里也能改默认值：

| 参数            | 默认  | 作用                       |
| --------------- | ----- | -------------------------- |
| `chunk_size`    | `512` | 每块大约多少字符           |
| `chunk_overlap` | `50`  | 相邻块重叠，避免句子被切断 |

Markdown 会按标题结构切。改分块不会重写已经入库的文档，需要重新上传。

上传会同时写入文档库、元数据和本地向量。任一步失败都会做补偿清理：API 已经报失败时，这条文档不应还能被检索到。存储是运行目录下的 SQLite，加上 `data/knowledge_base/` 里的 FAISS 索引，属于单进程单机部署。

## 接到会话

对话不会自动搜索你创建过的每一个知识库。需要在配置文件或规则里点名。

### 配置文件

**配置文件 → 知识库**：

| 字段              | 默认 | 说明                                   |
| ----------------- | ---- | -------------------------------------- |
| `kb_names`        | 空   | 本配置文件默认使用的知识库名称，可多选 |
| `kb_fusion_top_k` | `20` | 多库融合阶段保留的条数                 |
| `kb_final_top_k`  | `5`  | 最终注入或返回的条数                   |
| `kb_agentic_mode` | 关闭 | 见下一节                               |

空的 `kb_names` 表示这个配置文件不检索知识库。不同配置文件可以绑定不同名单，见 [配置文件](./config-profiles)。

### 自定义规则

规则里的 `kb_config.kb_ids` 会覆盖配置文件名单。空列表表示**这个会话不用知识库**。还可以单独设 `top_k`。见 [自定义规则](./custom-rules)。

知识库页的 **检索** 标签可以先拿一句话试召回，不必发到群里。

## Agentic 检索

默认（`kb_agentic_mode = false`）：每次 LLM 请求都会按用户这句话检索，结果作为临时上下文注入。

打开 Agentic 后：检索变成工具 `astr_kb_search`，由模型决定何时调用。需要模型支持函数调用，并且工具面板没有把该工具关掉。见 [函数调用](./function-calling)。

Agentic 适合「有时要查资料、有时只是闲聊」；默认注入适合「这个配置文件的对话几乎都要依据文档」。

## 常见误配

1. 知识库建好了，配置文件 `kb_names` 仍是空的。
2. 改了嵌入模型或维度，旧索引还在用。
3. 自定义规则的 `kb_ids` 指向已删除的库，看起来像「知识库没用」。
4. 打开 Agentic，但模型不支持工具或工具被 Persona 禁了。
5. 上传失败后仍能搜到半成品——这是缺陷，应视为异常并清理后重传。

如果出现这种情况，先不要继续上传同一文件：

1. 打开该知识库的文档列表，删除仍能检索到的残留文档；
2. 查看 AstrBot 启动日志和上传失败时间附近的错误；
3. 在知识库页的 **检索** 标签确认残留内容已经搜不到；
4. 再重新上传文件。无法删除或索引状态不一致时，先备份 `data/knowledge_base/` 和运行目录，再停止 AstrBot 后联系维护者处理，不要手工修改 FAISS 文件。
